# MiniGauge56 — Platform & Architecture Constraints

## 1. Hardware & Target

| Parameter | Constraint | Rationale |
| :--- | :--- | :--- |
| **Target SoC** | ESP32-S3, 240 MHz, 16 MB flash, octal PSRAM | Board fitted; PSRAM holds the LVGL draw buffer and the CAN ring buffer. |
| **Framework** | ESP-IDF v6.1 | `sdkconfig.defaults` and `dependencies.lock` are generated with 6.1.0 and CI builds with v6.1. The components declare `idf >= 5.5`, but other versions are not built or tested. |
| **CAN transceiver** | TX GPIO 43, RX GPIO 44, 500 kbps | Wiring of the board's transceiver path; bit rate is fixed in `twai_daemon`. |
| **Display** | 466x466 round AMOLED, CO5300 controller over QSPI, CST9217 touch | Driven by the `waveshare/esp32_s3_touch_amoled_1_75` BSP. |
| **SD storage** | MicroSD at `/sdcard`, FATFS through the BSP | `CONFIG_BSP_SD_FORMAT_ON_MOUNT_FAIL=y`: a card that fails to mount is formatted, erasing its contents. |

## 2. Software & Architecture

### 2.1 Component boundaries
- `twai_daemon` ([public repository](https://github.com/martinroger/twai_daemon)) and `bmwp2000` ([private repository](https://github.com/martinroger/BMWP2000)) are external git components fetched by the component manager into `managed_components/`. They are read-only here and changed in their own repositories.
- `bmwp2000` depends on `twai_daemon` without a version, which resolves to that repository's default branch and overrides the `v0.1.0` tag requested in `main/idf_component.yml`. `dependencies.lock` records the resolved commit.
- `components/lcd_emulator/` is in-tree and owned by this project.
- `components/ui/` is generated by EEZ Studio from `eezMG56.eez-project`; change the project file and regenerate instead of editing the sources.
- Warnings in external code are silenced at the root `CMakeLists.txt` (`-Wno-stringop-truncation` and others) rather than by editing components.

### 2.2 CAN receive hot path
- `app_can_frame_router()` runs in the `twai_daemon` RX worker task. Nothing it calls may block or allocate.
- `log_can_frame_handler()` builds the record on the stack and calls `xRingbufferSend(..., 0)`. A full buffer drops the frame.
- `bmwp2000_feed_can_frame()` must likewise return without waiting; queueing and filtering are the component's responsibility.
- A LID carries at most 10 CIDs (`bmwp2000` limit, also enforced by the LID composer).
- The `twai_daemon` RX queue holds 32 frames. If the router stalls, frames are lost at the queue.

### 2.3 Logging throughput
- The 32 KB ring buffer is a no-split buffer, so each 16-byte record also costs an item header; the usable capacity is roughly 1,300 records. That is the burst the writer can absorb while an SD write is in progress.
- Each block write is followed by `fsync`, which favours data safety over throughput.
- Records keep only 16 bits of the CAN ID. Supporting 29-bit IDs would need a format change in `main/logging.cpp` and in `tools/common/can_core.py`.

### 2.4 UI thread safety
- LVGL objects are touched only under `bsp_display_lock()`: 100 ms in `update_display()` and `sleepDisplay()`, 500 ms in `wakeDisplay()` (the boot-time first frame can hold the lock longer than 100 ms).
- LVGL event callbacks (`action_*`) run in the LVGL task and already hold the lock.
- Telemetry values cross from the `bmwp2000` callback to `upd_disp` as unsynchronised `double`s; this is acceptable for display only, not for anything that needs consistent values.

### 2.5 Display and burn-in
- Brightness is set to 40 % on every wake, in both modes.
- Always-on is the boot default. With it off, the backlight turns off after 10 s without touch.

### 2.6 LVGL colour depth
- LVGL renders at 8 bits per pixel (`CONFIG_LV_COLOR_DEPTH_8`) and `lcd_emulator` expands to RGB565 for the panel. Code that draws images or uses colour must work in L8.

## 3. Build, CI & Repository

- **Toolchain**: ESP-IDF installed with the Espressif Installation Manager (`eim`) with the `mcp` feature; toolchains live under `~/.espressif`, outside the repository.
- **Build server**: the Espressif Tools MCP server (`idf.py mcp-server`, ESP-IDF >= v6.0) is registered in [.mcp.json](../.mcp.json) as `esp-idf-eim`, pinned per invocation to v6.1 (`eim run "idf.py mcp-server" v6.1`). It is a local stdio process with no network listener or credentials.
- **MCP-first rule**: agents use the MCP tools (`set_target`, `build_project`, `flash_project`, `clean_project`, resources `project://status|config|devices`) when the server is connected. Fallback: `eim run "idf.py fullclean build" v6.1`.
- **Clean rule**: `clean_project` (or `fullclean`) after any change to `Kconfig`, `Kconfig.projbuild`, `sdkconfig` or `sdkconfig.*`, at session start and after a branch switch.
- **Private dependency**: building needs read access to `martinroger/BMWP2000`. In CI this is the `PRIVATE_REPOS_TOKEN` repository secret, a fine-grained token with read-only Contents access. CI jobs triggered from forks get no secrets and cannot build.
- **Lock file**: `dependencies.lock` is tracked (exempted from the `*.lock` ignore rule) and must be committed when dependencies change.
- **Privacy invariant**: `.mcp.json` and all committed docs, hooks and skills must not contain absolute home paths (`/Users/<name>`, `/home/<name>`), `IDF_PATH` values, tokens or credentials. `sdkconfig`, `sdkconfig.old`, `build/`, `*.log` and `.espressif/` stay untracked.
- **Hooks**: `.githooks/pre-commit` rejects staged files with absolute home paths or common secret patterns; `.githooks/pre-push` runs a test runner if the repository provides one. Install with `.githooks/install.sh`.
