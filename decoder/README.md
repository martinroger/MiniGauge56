# MiniGauge CAN Log Tools

This folder contains standalone tools to decode and visualize binary CAN bus log files (`log_*.bin`) generated by the MiniGauge ESP32 firmware using the CAN database (`binocan.dbc`).

Both tools are written in pure Python 3 and have **zero external pip dependencies**.

---

## 1. Batch Decoder (`decode.py`)

Parses 16-byte packed binary CAN logs into standard Vector ASCII (`.asc`) and decoded (`.csv`) files.

### Binary Record Layout
As implemented in `main/logging.cpp`:
- `uint32_t timestamp`: 4 bytes (ESP32 uptime in milliseconds)
- `uint16_t id`: 2 bytes (CAN arbitration ID)
- `uint8_t dlc`: 1 byte (Data Length Code, 0–8)
- `uint8_t data[8]`: 8 bytes (Payload bytes)
- `uint8_t padding`: 1 byte (Brings total to 16 bytes)

### Usage

```bash
# From within the decoder directory:
cd decoder

# 1. Decode all .bin files in current folder to .csv and .asc
python3 decode.py

# 2. Also export flat signal time-series CSVs (_signals.csv)
python3 decode.py --signals

# 3. Also export wide time-series matrix CSVs (_wide.csv)
python3 decode.py --wide

# 4. Decode a specific file and save to a custom output directory
python3 decode.py log_42878613.bin --output-dir ./export/
```

### CLI Arguments

| Argument | Description |
|---|---|
| `inputs` | One or more `.bin` file paths (default: all `log_*.bin` in folder) |
| `--dbc, -d <file.dbc>` | Path to DBC database (default: `binocan.dbc`) |
| `--output-dir, -o <dir>` | Destination folder for exports (default: input folder) |
| `--asc-only` | Output only Vector `.asc` files |
| `--csv-only` | Output only decoded `.csv` files |
| `--signals, -s` | Also generate flat `_signals.csv` time series |
| `--wide, -w` | Also generate wide `_wide.csv` matrix where each signal is a column |

### Generated Outputs

- **`.asc` (Vector ASCII)**: Industry standard format compatible with Vector CANoe, CANalyzer, SavvyCAN, and Asammdf.
- **`.csv` (Decoded Message Log)**: Columns: `timestamp_ms`, `time_s`, `can_id`, `can_id_dec`, `message_name`, `dlc`, `data_hex`, `signals` (readable formatted text), and `signals_json`.
- **`_signals.csv` (Flat Signals Table)**: Columns: `timestamp_ms`, `time_s`, `can_id`, `message_name`, `signal_name`, `value`, `unit`, `state`.

## 2. Interactive Signal Visualizer (`visualize.py`)

A browser-based interactive dashboard that decodes `.bin` files on-the-fly and plots multiple signals against time.

### Features
- **Zero Configuration**: Starts a local web server on `http://localhost:8080` and opens your default browser automatically.
- **On-the-Fly Decoding**: Reads directly from `.bin` files using `binocan.dbc`.
- **Log Switcher**: Dropdown in the header allows switching between log files instantly.
- **Searchable Multi-Select**: Filter signals by name, unit, or CAN message group.
- **Quick Presets**: One-click filters for *Fuel & Power*, *Coolant & Temp*, *Speed & RPM*, and *Telltales*.
- **Multi-Axis Overlay**: Automatically gives distinct, color-coded Y-axes to signals with different engineering units (`V`, `Hz`, `kph`, `Ohm`) so they don't distort each other.
- **Stacked Subplots Mode**: Toggle between overlaid multi-axis view and vertically stacked synchronized subplots.
- **Plotly.js Chart Controls**:
  - Drag to zoom into any time range or box.
  - Hover tooltip displays exact timestamp, signal value, unit, and enum states (e.g. `1 (HI)` or `0 (Neutral)`).
  - Reset view button.
  - One-click PNG export.

### Usage

```bash
cd decoder
python3 visualize.py
```

### CLI Arguments

| Argument | Description |
|---|---|
| `log_file` | Optional initial `.bin` file to open |
| `--port, -p <port>` | HTTP server port (default: 8080, auto-increments if busy) |
| `--dbc, -d <file.dbc>` | Custom DBC file path |
| `--no-browser` | Do not launch the browser automatically |
